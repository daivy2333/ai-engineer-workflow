# 宏观探究

## 目录

- Phase 1：规划
- Gate 1
- Phase 2：调查
- Gate 2
- Phase 3：报告

## Phase 1：规划

1. 扫描仓库结构、入口、构建文件和主要模块。
2. 复用当前会话中已有的 SNAPSHOT、分析、project-model、decisions、knowledge 和活跃 change 信息，只补读当前主题缺失内容。
3. 对已有主题做去重检查。
4. 拆分 3-8 个主题：
   - 当前项目描述引用 SNAPSHOT，不设独立概览主题。
   - 其余主题按项目结构和用户目标选择。
   - 活跃 change 涉及的模块优先。
5. 对每个主题列出：
   - 目标问题。
   - 初始文件和符号。
   - 文档模式下的输出文件名。
   - 与其他主题的关系。
6. 确定即时回答或文档模式。
7. 用户已明确指定主题和顺序时直接执行；否则展示主题和顺序并请求批准。

## Gate 1

- 主题覆盖用户目标。
- 每个主题有明确范围。
- 去重检查完成。
- 输出模式明确。
- 主题和顺序已由用户明确指定或批准。

## Phase 2：调查

按批准顺序处理每个主题：

1. 找入口和关键符号。
2. 阅读关键实现。
3. 追踪调用者和被调用者。
4. 记录状态、数据流、错误和并发边界。
5. 定位与目标有关的测试、验证入口和影响面，区分已运行结果与未验证入口。
6. 即时回答模式保留回答所需证据，不创建文件。
7. 文档模式生成 `.claude/analysis/<topic>.md`。
8. 文档模式更新同批文档的双向 See also。
9. 文档模式为每份文档生成 R 候选。

宏观分析聚焦 SNAPSHOT 不保存的关系和问题：

- 主要依赖方向。
- 跨模块调用、数据流和状态变化。
- 错误、并发和资源边界。
- 与目标相关的未确认问题。

## Gate 2

- 每个主题回答对应问题。
- 文档模式下，文档间引用有效。
- 关键模块没有无解释遗漏。
- 所有结论有代码或项目文档依据。
- 文档模式下，R 候选已经形成。

## Phase 3：报告

报告：

- 输出模式。
- 生成的文档或即时回答。
- 关键发现。
- 依赖关系。
- 与用户目标和活跃 change 的关系。
- 未确认问题。
- 文档模式下的 R 登记结果。
- 未自动登记的 M/D/K/I 候选。

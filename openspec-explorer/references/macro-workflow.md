# 宏观探究

## 目录

- Phase 1：规划
- Gate 1
- Phase 2：调查
- Gate 2
- Phase 3：报告

## Phase 1：规划

1. 扫描仓库结构、入口、构建文件和主要模块。
2. 读取 SNAPSHOT、已有分析、learned、architecture 和活跃 changes。
3. 对已有主题做去重检查。
4. 拆分 3-8 个主题：
   - 项目概览必须存在。
   - 其余主题按项目结构和用户目标选择。
   - 活跃 change 涉及的模块优先。
5. 对每个主题列出：
   - 目标问题。
   - 初始文件和符号。
   - 文档模式下的输出文件名。
   - 与其他主题的关系。
6. 确定即时回答或文档模式。
7. 请求用户批准主题和顺序。

## Gate 1

- 主题覆盖用户目标。
- 每个主题有明确范围。
- 去重检查完成。
- 输出模式明确。
- 用户批准主题和顺序。

## Phase 2：调查

按批准顺序处理每个主题：

1. 找入口和核心符号。
2. 阅读关键实现。
3. 追踪调用者和被调用者。
4. 记录状态、数据流、错误和并发边界。
5. 即时回答模式保留回答所需证据，不创建文件。
6. 文档模式生成 `.claude/analysis/<topic>.md`。
7. 文档模式更新同批文档的双向 See also。
8. 文档模式为每份文档生成 R 候选。

项目概览建议覆盖：

- 仓库结构。
- 技术栈和构建系统。
- 运行入口。
- 模块边界。
- 主要依赖方向。
- 测试和验证入口。

## Gate 2

- 每个主题回答对应问题。
- 文档模式下，文档间引用有效。
- 关键模块没有无解释遗漏。
- 所有结论有代码或项目文档依据。
- 文档模式下，R 候选已经形成。

## Phase 3：报告

报告：

- 输出模式。
- 生成的文档或即时回答。
- 关键发现。
- 依赖关系。
- 与用户目标和活跃 change 的关系。
- 未确认问题。
- 文档模式下的 R 登记结果。
- 未自动登记的 A/L 候选。

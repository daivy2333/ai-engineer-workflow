# 微观探究

## 目录

- Phase 1：聚焦
- Gate 1
- Phase 2：深入
- Gate 2
- Phase 3：报告

## Phase 1：聚焦

1. 把用户目标改写成 3-8 个可回答问题。
2. 检查已有 analysis、learned、architecture 和相关 change。
3. 确定入口文件、关键接口、状态和依赖深度。
4. 范围不确定时请求用户确认。

## Gate 1

- 目标和问题明确。
- 范围不过大也不过小。
- 已完成去重。
- 初始文件和符号可定位。

## Phase 2：深入

1. 阅读目标入口的完整上下文。
2. 追踪上游消费者。
3. 追踪下游依赖。
4. 记录动态调用边。
5. 检查错误、取消、并发和资源生命周期。
6. 评估受影响符号和模块。
7. 生成 1-2 份聚焦分析。
8. 生成 A/L/R 候选交接清单。

## Gate 2

- 每个问题都有证据支持的答案。
- 关键调用链没有无解释断点。
- 边界和未知项已标明。
- 文档能支持后续设计或实施。
- A/L/R 候选已交给 maintainer。

## Phase 3：报告

报告：

- 已回答问题。
- 与任务相关的发现。
- 分析文档路径。
- 相关 change。
- 未确认项和下一决策点。

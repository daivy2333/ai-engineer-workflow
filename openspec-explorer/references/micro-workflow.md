# 微观探究

## 目录

- Phase 1：聚焦
- Gate 1
- Phase 2：深入
- Gate 2
- Phase 3：报告

## Phase 1：聚焦

1. 把用户目标改写成 3-8 个可回答问题。
2. 检查已有 analysis、project-model、decisions、knowledge 和相关 change。
3. 确定入口文件、关键接口、状态和依赖深度。
4. 确定即时回答或文档模式。
5. 范围不确定时请求用户确认。

## Gate 1

- 目标和问题明确。
- 范围不过大也不过小。
- 已完成去重。
- 初始文件和符号可定位。
- 输出模式明确。

## Phase 2：深入

1. 阅读目标入口的完整上下文。
2. 追踪上游消费者。
3. 追踪下游依赖。
4. 记录动态调用边。
5. 检查错误、取消、并发和资源生命周期。
6. 评估受影响符号和模块。
7. 定位相关测试和验证入口，区分已运行结果与未验证入口。
8. 即时回答模式整理回答和证据，不创建文件。
9. 文档模式生成 1-2 份聚焦分析。
10. 文档模式为每份文档生成 R 候选。

## Gate 2

- 每个问题都有证据支持的答案。
- 关键调用链没有无解释断点。
- 边界和未知项已标明。
- 输出能支持后续设计或实施。
- 文档模式下，R 候选已经形成。

## Phase 3：报告

报告：

- 已回答问题。
- 与任务相关的发现。
- 分析文档路径或即时回答。
- 文档模式下的 R 登记结果。
- 相关 change。
- 未确认项和下一决策点。

## Project Docs Assistant

**日常开发的文档管家，按需取用，精准更新。**

---

## 核心触发模式

| 触发词 | 行为 | 读取 | 写入 |
|--------|------|------|------|
| 恢复上下文 / 当前进度 | 汇总项目状态 | snapshot.md + tasks.md | 无 |
| 更新快照 / 同步状态 | 同步项目当前状态 | snapshot.md | snapshot.md |
| 更新任务 | 反映任务进度 | tasks.md | tasks.md |
| 记录决策 | 追加架构决策 | architecture.md | architecture.md |
| 查询规范 | 展示编码规范 | rules.md | 无 |

## 模式执行流程

### 模式 1: 恢复上下文

**触发**: "恢复上下文"、"当前进度"、"我们进行到哪了"、"继续之前的工作"

**执行**:
1. 读取 `.claude/snapshot.md` → 获取项目状态、结构、最近修改
2. 读取 `.claude/tasks.md` → 获取进行中和待办任务
3. 汇总呈现：
   - 当前阶段和状态
   - 进行中的任务
   - 下一步计划
   - 阻塞点（如有）

### 模式 2: 更新快照

**触发**: "更新快照"、"同步项目状态"、"记录当前进度"

**执行**:
1. 读取 `.claude/snapshot.md`
2. 扫描 git 状态（分支、最近提交、未提交更改）
3. 检查项目结构变化（如有）
4. 更新变动部分：
   - Git 状态
   - 最近修改记录（追加）
   - 项目结构（如有变化）
5. 保留历史记录，只追加不删除

### 模式 3: 更新任务

**触发**: "更新任务"、"完成了 X"、"接下来的任务是 Y"、"把 X 加到待办"

**执行**:
1. 读取 `.claude/tasks.md`
2. 根据用户描述：
   - 完成项：从"进行中"移到"最近完成"
   - 新任务：添加到"待办"或"进行中"
   - 阻塞项：记录阻塞原因
3. 更新"下一步"计划
4. 只修改变化部分，保持结构稳定

### 模式 4: 记录决策

**触发**: "记录一个决策"、"我们决定用 X"、"ADR"

**执行**:
1. 读取 `.claude/architecture.md`
2. 在决策列表顶部追加：
   ```
   ### {DATE} - {决策标题}
   - **决策**: {决策内容}
   - **原因**: {原因}
   - **影响**: {影响范围}
   - **替代方案**: {考虑过的其他方案}
   ```
3. 不修改已有决策

### 模式 5: 查询规范

**触发**: "查询规范"、"编码规范是什么"、"我应该遵循什么原则"

**执行**:
1. 读取 `.claude/rules.md`
2. 根据任务类型提取相关部分：
   - 新功能：Karpathy Guidelines + 务实编码原则
   - Bug 修复：Surgical Changes + Goal-Driven Execution
   - 重构：DRY & 正交性 + 尽早重构
3. 展示检查清单和 Red Flags

## 次级操作（不单独触发，作为附加）

用户在主模式中可顺便请求：

- **添加参考**: "顺便把这个链接加到参考" → 追加 references.md
- **记录优化点**: "这个以后要优化" → 追加 optimization.md

---

## 文档修改铁律

- 只修改与请求直接相关的部分
- 不"顺便"调整格式、重写无关内容
- 追加新内容时保持原有结构
- 只在修改的文件中更新时间戳

---

## 关键原则

```
按需加载，最多读 2 个文档
精准修改，只动必要部分
保持稳定，追加不删除
保留历史轨迹
```

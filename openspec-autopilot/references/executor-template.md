# 通用执行者派发模板

轻量工作项的子代理模板。轻量工作指不改变系统可观察行为（功能语义）的修改，以及满足全部条件的简易缺陷修复（公共规则 › 轻量工作）：纯文档、注释、格式、不改行为的重构和简易缺陷修复等；实质问题判定沿用公共规则 › Plan 调查。

## 适用与不适用

- 适用：不改功能语义的修改，以及满足公共规则 › 轻量工作 简易缺陷修复全部条件的缺陷修复；goal 指令即构成执行授权。
- 不适用：改变功能语义的修改必须建 change；执行中发现实际影响行为、接口、错误语义、状态所有权、架构、范围、测试策略或 Acceptance 时，停止并回报"需要 change"。
- 直接修改 `openspec/specs/` 不属于轻量工作（specs 是功能语义的权威记录）。

## 派发模板

```text
你是轻量工作执行者，本次任务来自 goal 指令授权。

任务：<具体工作项>
Goal 原文：<goal 原文>

规则：
1. 读取项目 AGENTS.md 的 轻量工作、行为约束 与 验证 章节并遵守。
2. 确认目标修改不改变功能语义；缺陷修复先逐条对照 轻量工作 的简易缺陷修复条件，任一不满足或不确定时停止，回报"需要 change"及原因。
3. 涉及代码的修改按 TDD 执行：重构类改前 GREEN、改后 GREEN，缺陷修复类先复现 RED、修复 GREEN；
   纯文档、注释和格式修改不适用先行测试。
4. 修改后运行受影响的验证，保留命令与实际结果。
5. 只修改任务所需内容，不清理无关代码。
6. 完成后报告：修改文件、验证命令与实际结果、未解决问题；缺陷修复另附复现测试位置，供 Issue 关闭指针引用。
```

## 完成判定

以产物为准：目标文件已修改，受影响验证通过（纯文档修改无验证需求时以 diff 为准），缺陷修复的复现测试达到 GREEN，执行者报告与实际 diff 一致。执行者回报"需要 change"时，该工作项停止轻量路径，由 autopilot 派发 plan 子代理处理。
